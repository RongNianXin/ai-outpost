# 隐私边界框架（讨论稿）

状态：讨论中，未作为运行规则或产品功能采用。

## 目标

允许开源项目公开“如何隔离私密上下文”的方法，同时不把任何具体私密内容、关系、来源名单、凭据或内部评价带入公开仓库、公开构建或跨项目协作。

## 拟采用的分层

1. **公开规则层**：只描述分类、访问边界、脱敏要求、失效条件和核验方法，不保存具体秘密。
2. **本机私密层**：保存私密事实和必要的恢复内容，位于明确被忽略的目录；公开索引只保存不含正文的指针。
3. **交接层**：同一项目换任时，新总指挥在正式取得权限后按指针回读；跨项目、专项任务和独立审查只接收脱敏规则，不接收私密正文。
4. **外发门禁层**：公开稿、Issue、PR、日志、自动化提示词和平台草稿生成前检查是否混入私密字段；发现混入先停止受影响动作。

## 当前不承诺的部分

- `.gitignore` 只能阻止正常 Git 跟踪，不能防止本机管理员、备份软件、恶意程序、编辑器历史或聊天平台读取。
- 未实现加密存储、密钥管理、加密迁移、远端密文备份或可证明删除。
- 同机目录丢失、换电脑或账号变化时，私密上下文不能自动恢复；迁移必须由操作者另行选择加密方式、接收对象和恢复验证。
- “公开框架存在”不等于任何具体隐私内容已经安全，也不等于完成了历史 Git/远端清理。

## 采用前必须解决的问题

- 加密方案和密钥归属；
- 同机换任与跨设备恢复的最小人工步骤；
- 公开状态和远端历史的自动脱敏检查；
- 密钥丢失、私密目录损坏、错误外发和恢复失败的处理；
- 如何在不读取私密正文的情况下向其他项目证明“该字段受隐私边界保护”。

本讨论稿不包含任何具体私密事实，不授权提交、推送、备份、外发或启用新的隐私功能。
