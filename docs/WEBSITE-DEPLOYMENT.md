# 官网本机产物发布

本流程替代将当期期刊 JSON 提交到远端后构建的旧官网适配器。每期源稿、来源库、运行记录和媒体稿包只留本机；远端只接收经过逐文件检查的公开静态网页部署包。公开网页本身仍含作者明确同意发布的文章和引用，不是私密内容备份。

## 前置条件

1. 作者确认精确官网版本及发布；封面文字单独审定，缺图不冒充有图。
2. 发布前重新加载来源库并补查官方变化；有实质变化回到审稿，只暂停受影响动作。
3. 本机 `ops/weekly-run-state.json` 为 normal 且绑定本期，暂停与紧急停止仍阻断。将作者已批准稿准备为 published 构建候选；实际部署状态单独记录，失败不能称已上线。
4. 内容校验、当期链接、类型、lint、相关测试和生产构建通过；审核构建产物中的全部正文、来源、手机显示和下载。

## 仓库与部署分开

`.gitignore` 阻止新文件，远端边界检查阻止已跟踪或强制暂存的私有文件进入新提交。现有远端历史素材不会因忽略规则消失；不改写历史或批量删除旧期。规则、代码和 CI 修复在从当前远端基线建立的隔离工作区定点提交，不推送主工作区分叉历史，不复制私密库到工作区。隔离隐私检查仅用只读环境变量指向已有私密库。

构建在本机完成，设置 `NEXT_PUBLIC_BASE_PATH=/ai-outpost`。只对 `out` 建立部署归档：

```powershell
python scripts/publish/pages-bundle.py --source out --archive .local/pages-deploy/site.tar.gz --slug <slug>
```

检查拒绝隐藏路径、源码目录、未允许的文件类型、源码映射、符号链接、路径穿越、本机私密路径及凭据标记；要求首页、归档、关于页、本期详情和下载齐全。还要人工/脚本对照公开产物与作者批准版本、隐私比较库，不能只凭扩展名声称无泄漏。

代码与 README 最新一期在同一候选提交中同步；推送前检查 staged 和相对最新远端的整个候选差异，保留先前公网版本及部署包用于回滚。只有当前发布所需的代码和公开入口说明可进入提交。

上传入口：

```powershell
pnpm.cmd exec tsx scripts/publish/deploy-public-bundle.ts --issue content/issues/issue-NNN.json --archive .local/pages-deploy/site.tar.gz --code-sha <远端代码完整SHA> --confirmation 发布官网第NNN期
```

上传脚本逐个外部写入前回读当期运行门禁。公开静态包暂存于本仓库一个临时 draft Release，仅含 `site.tar.gz`，不发布 Release，不上传源稿或记录。Actions 只下载匹配当前代码提交的本仓库草稿包，校对 SHA256 并再次检查归档，然后部署 Pages；不从仓库历史期刊重建。归档和回执留在本机，失败保留草稿包供诊断或重试，不自动再次发送。

## 收口与回滚

等待确切 workflow run 完成，核对公网首页、归档、本期全文、来源、下载和远端 README 的同期状态；只有这些证据齐全才能称发布完成。删除本轮临时 draft Release；Pages artifact 保留一天用于恢复，长期回滚包留本机。若部署失败而 README 已变更，在同一隔离通道恢复先前 README，保留线上旧部署，不删除旧记录、不强推。公开回读后恢复本机 draft_only，绑定本期并保留实际回执。媒体平台仍分别授权，不随官网发送。
