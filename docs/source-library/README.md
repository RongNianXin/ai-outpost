## 如何使用

先查目录中的模型/Agent官方入口，再参考中文媒体和社区找遗漏与问题。每期读已有目录，不从空白提示词重新想名单；核心官方入口逐个检查，社区与研究按本期主题选择并记录缺口。新增来源可随时登记为候选，不能让目录成为封闭白名单。

机器之心、量子位已登记为非模型厂商官方的科技媒体，用户推荐是发现理由，不是质量证明；网站属于媒体自己的官网，并不使其成为模型厂商官方来源。微信公众号具体账号须由其官网链接/二维码或认证信息核验，未核验不编造公众号ID或同名账号链接。

OpenAI开发者社区有ChatGPT和Codex板块；Claude官方社区页提供Discord入口。官方承载的社区与发帖者身份分开。知乎本次安全验证，量子位直接读取失败，Claude Discord未登录或加入；不得称这些平台热帖已全文审阅。

看社区时使用本期时间窗，记录采集时刻、帖子发布时间/最后活动时间、可见回复/浏览/赞数和原帖。新回复顶起的旧帖不是新发布；没有周榜就用可见样本，不说“全站最热”。争议、故障与抱怨也可能热，不等于正面反馈。将线索改写为检索问题，再查原始公告/实验；不复制媒体结构、段落或配图，不把换词当原创。

## 简版评价

不自称有真实的多年博主从业经历。采用编辑工作中的实用尺度，每项记录高/中/低/待确认及证据，不用虚构精确总分：

| 维度 | 要检查的事 |
| --- | --- |
| 相关性 | 能否持续提供Agent、重大模型或应用开发相关线索 |
| 可追溯性 | 能否找到原文、作者、日期、方法和原始链接 |
| 准确与克制 | 抽查本轮实际使用文章：标题兑现，区分事实和判断，保留限制 |
| 纠错与利益披露 | 错误是否修正，赞助/提前体验是否披露；没找到不等于没有 |
| 信息增量与成本 | 是否帮助发现遗漏；登录、误报和验证成本是否值得 |

首次登记没有文章样本时，准确性、纠错记录保持待确认。每次发布后复盘本期实际用过的来源，累计3–5篇真实样本后决定常用、观察、降级或暂停；3–5篇只是轻量抽样，不证明全部文章质量。粉丝量与操作者偏好不计质量分。严重伪造、身份冒用、反复无法追溯可立即暂停；访问失败只降低可用性，不能据此认定主体不良。

## 主体与文章双层敏感性审查

1. 主体：确认实际发布组织/个人及其与平台关系，查公开身份、必要时检索重大争议并回溯原文/可靠处理记录。实名主体不明、指控无法证实列待确认，不贴“反华/反动”等未经证实标签，不因国籍或任职公司推断政治立场。
2. 内容：逐篇检查针对中国人或其他群体的侮辱/仇恨、煽动暴力、政治动员、违法内容、隐私泄漏及明显误导。与本刊无关的政治争论不选；报道或批评某事件不等于支持事件，不机械按敏感词封禁技术安全讨论。
3. 处置：有可靠证据表明主体存在与本项目风险直接相关的严重问题，暂停该主体的引用，记录证据、时间、范围与复核条件。仅单篇问题先暂停该篇；平台上个别用户问题不能推及全部用户。可回到独立原始技术来源重新核验，不能借转引掩盖风险主体。
4. 每次结论明确范围：入口核验、有限抽样、待核验或暂停。不得声称“从无污点”“已经全网排查”“保证不会影响账号”。未完成主体/文章审查的条目仅是检索线索，不作为发布通过名单。

首轮覆盖25条的入口/角色/可见内容分流，后续扩展9条的审查见下节，状态详见catalog；主体历史与文章级检查仍有限或待做。额外负面线索搜索覆盖机器之心、量子位、Artificial Analysis、Claire Vo；结果中的转载、同名词和论坛指控不足以定性，未据此给主体贴标签。不是完整政治背景调查。

## 不依赖定时器的维护触发

- 新期检索开始：读目录，运行周状态检查；重查必用入口及已过期/受限项。
- 每次发布前：审查实际引用主体、文章与链接，执行重大消息增量补查；只阻断受影响稿件。
- 每次发布完成后：记录本期命中、误报、纠错、访问成本，更新本期使用来源及发现的新候选。其他本地指南/工具入口有变化同时更正，以各自现有文档为唯一入口。
- 旧总指挥总结并生成交接快照后：核对目录与工具/资料指针、失效项、待审项、未提交文件和未完成周状态；如有更新，补写快照的最终版本与指纹，避免“快照生成后修改但快照仍旧”。不再创建第二套状态库。
- 新总指挥恢复：复核目录日期、待办与旧快照增补；不因换任重置评价历史或继承发送/调度授权。
- 重大纠错、域名/主体变化、连续访问失败：当次任务立即复核。没有运行中的任务或操作者触发时，不承诺后台持续更新。

触发动作在AGENTS与CONTENT-OPS中设入口；维护记录归progress/findings，目录保存当前结论。长期未用来源下次实际使用前重查，不机械每周全文审所有历史主体。

## 漏执行检查的使用

在项目恢复、生产开始、发布收尾与交接收尾执行：

~~~powershell
node scripts/ops/check-weekly.mjs
~~~

输出本地记录中的到期周、未开始/中断/待审/已公开，以及调度暂停状态。目的：防止错过某周或重复生成；本地公开状态不能冒充公网回读。异常时保留输出，核对状态与期刊，不自动修改它们。

需要去重本地提示时加 --record，只记录控制台展示回执到忽略目录.local；不是邮件或桌面送达证明。脚本不登录Codex、不发消息、不启任务；可在终端直接执行，但没有注册登录监听或计划任务，因此无人调用时不会自行提醒。

演练：node --test scripts/ops/check-weekly.checks.mjs 。首个计划检查周为2026-09-12，依据003期计划；启用周任务前需核对这一基点、期刊周期和状态。无需把真实状态改成假失败来测试。
