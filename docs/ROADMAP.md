# 产品路线

## V1：低维护资讯产品

目标是验证内容是否对项目作者和同类读者有用，并建立每周可持续的生产流程。

### 阶段

1. 治理基线：产品、架构、内容规范和版本规则。
2. 可运行骨架：Next.js 静态导出与 GitHub Pages 工作流。
3. 内容引擎：结构校验、内容加载和公众号导出。
4. MVP 页面：最新一期、归档、详情和方法说明。
5. 第一期演练：官方来源收集、AI 质检、自动化校验和本地预览。
6. 公开发布：浏览器验收、部署和访问检查。

## V1.5：稳定周更自动化

公开发布完成后优先进入本阶段。目标不是扩展社媒，而是验证“官网主站能否以低人工介入方式稳定周更”。

### 第一阶段

- 建立每周运行状态：`normal`、`paused`、`draft_only`、`emergency_stop`。
- 把第 002 期生产流程拆成候选收集、去重、事实映射、AI 交叉核验、中文草稿、发布前检查和确认上线。
- 保留人工确认关卡；AI 全部检查通过后仍只能进入“等待确认发布”。
- 内容不足时允许短版或跳过，并保留跳过原因。
- 记录每周运行日志、候选淘汰原因、失败原因和最终发布状态。

### 第二阶段

- 将高频对话式操作固化为脚本命令或半自动任务包。
- 生成官网发布包和可选分享包。
- 尝试通知机制：优先微信/企业微信，接口能力待确认；邮件或 GitHub Actions 作为兜底。
- 加入预算控制：候选数量、AI 调用轮次、重试次数和发布尝试次数。

### 暂不做

- 不自动发布到微信公众号、小红书或 X/Twitter。
- 不要求用户注册或运营不熟悉的平台账号。
- 不为了平台传播提前建设复杂后台。

## V2：内容生产辅助与分享包

只有连续运行 4 至 6 期后才决定是否进入。

候选能力：

- 将 V1 的对话式 AI 收集、去重和评分固化为可重复运行的脚本或服务
- 自动维护来源状态、运行记录和失败重试
- 多平台标题、摘要、发布文案和小红书图文卡片生成
- 官网合集页、月度回顾页、RSS、站点地图和搜索收录辅助
- 视频选题、钩子和脚本草稿

所有输出继续要求官方来源可追溯，并通过自动化校验；重要信息以官方链接为准。

## V3：视频工作流

根据内容受众和运营价值再决定是否投入：

- 按抖音、小红书和 B 站分别生成脚本
- 生成分镜、字幕和合法素材建议
- 配音与剪辑辅助
- 平台发布文案

V1/V1.5 仅保存可复用的传播观点、演示可能性和视觉提示，不建设媒体系统、自动剪辑或自动发布能力。

## 延后判断

登录、数据库、个性化和动态服务只有在明确出现用户数据或实时功能需求时再引入。静态站不是永久限制，而是当前最小成本的发布方式。
