### 作者立场审定：白话确认与逐句对照

先完成下列内容审定，再交付排版；已有稿件也可按此局部复核。适用于本项目官网和社媒派生稿，不要求所有文章机械采用三条立场。

1. **AI先说明对象。**用读者能理解的话解释栏目在帮谁、解决什么问题；如果说“六条资讯”，先明确它是文中的六个小节，不是六个问题。优先复用作者已经说明的目的，不索要空泛自述。
2. **呈现可审定的具体意见。**从实际稿件抽取少量关键判断，逐条注明位置和白话含义，区分新闻事实、他人测评与本刊意见。用户只需指出认可、不同意或看不懂的部分，也可自由补充；不让其找术语、查技术参数或凭空编写体验。看不懂时解释具体句子，不反复发同一填空模板，也不诱导其答“全都同意”。
3. **AI完成全文对照。**检查标题、导读、建议和限制是否忠实于已确认立场。列出“原句→建议句→依据”，分清必须修改与可选润色；原文一致就不改。来源可靠性、事实与技术参数仍由AI核验，用户的态度不能替代证据。
4. **记录后继续，不机械确认。**当期立场与对应稿件版本记入task_plan/progress，后续只对新增观点、实质改动或新反证请求局部审定。改稿授权只列实际必要动作，允许把本地改句、审校、完整性检查和打开预览合并一次；后台操作和公开发布保持各自授权。

对抗式边界：白话概括不得遗漏原句的条件，不将多个有争议观点揉成一句安全口号。作者认可三句话不等于认可所有技术细节、已经逐字审稿或获得原创/发布资格；不为了规避平台检测添加假经历，不用“人工确认过”替代实质贡献证据。固定排版模板不等于套路化内容，不能为求变化无故重排整篇。

## 标准工作流

1. **确认状态**：读运行模式与最新期刊。暂停/紧急停止不得外发，draft_only 只做本地准备。预览通过和最终发布授权分开。
2. **周六 10:00 刷新**：本机 Codex 任务检索当周周一至实际截止时刻。设备和 Codex 需可运行；错过后先检查执行记录，不假定自动补跑。
3. **选题与核验**：先找本周最重磅三项，最多保留六条。官方核实产品事实；独立测评及可信博主一手记录补充体验，分别注明来源、条件与局限。交稿前再次检查重磅遗漏。
4. **共同底稿集中审查**：先完成一期 JSON 的事实、来源、数字、限制、标题导读、建议、文风、标点与错别字检查，再与作者已确认立场逐句对照。集中列出必要改句和依据，一次修订；不等官网先发后才首次审公众号内容。将定稿的文件指针、内容指纹及作者确认记在现有任务记录，不另建事实库。指纹只识别内容版本，不产生发布许可。
5. **派生、对照与真实预览**：从同一底稿生成本轮计划发布的平台材料及 Markdown；逐项对照关键结论、数字、来源归属和限制。允许标题长度、段落和样式适配，不允许改变结论或删掉支撑该结论的条件。AI检查结构、链接、测试、构建、图片、下载及本地预览；作者集中粘贴上传后再核验平台全文和手机效果。截图只证明可见范围，不能凭首尾段或小节数量宣称全文一致。公众号另查原创、AI标识、素材权利和平台创作规则。改稿后只重验受影响部分及其依赖，未筹备平台不成为全局阻断。
6. **保存工程版本**：首次本地执行建议应把修复、验证、审查与本地保存一起列清；已获相应授权且无需中间人工验收时连续完成，不重复确认。先核对精确范围和敏感文件，不能跳过校验或随便全量提交；提交本地不等于授权推送。
7. **最终确认官网**：确认具体期号/版本、目标仓库与发布影响，才可推进公开状态、推送和部署。等待部署完成并访问公开文章；下载文件与该版本一致后，才准备外部分发。
8. **分别分发**：小红书先私密测试；公众号先草稿箱测试。公开文章里的官网链接必须真实可访问。每种外部写入单独确认；任一渠道受阻不阻断其他已满足条件的渠道。
9. **轻量推广与复盘**：按本文现行渠道试验筛选明确接受相关内容的位置；只在最终授权后发送。整理主动反馈及平台实际可见数据，不主动群发、私信邀读，不把不同平台指标相加，不默认新增追踪器或定时监控。

### 发布后分级纠错与跨平台同步

集中审查能减少返工，不能保证以后不会发现问题；“统一”指共同事实和明确版本，不要求所有平台同一天发布，也不是一键全发。

| 等级 | 判断依据与处理 |
| --- | --- |
| 紧急纠错 | 错误事实、关键数字、归因、隐私或安全建议可能实质误导读者：立即报告、暂停受影响版本继续分发，准备更正或撤回建议；按实际风险优先处理，不因等齐其他平台拖延。不自动取得撤回、后台修改或部署权限。 |
| 澄清修订 | 标题省略条件、容易误读的测评归属等，正文证据和核心结论未变：列出原句→新句→理由→受影响载体，集中在下一次获准更新中同步；若误读后果升高，升级处理。 |
| 可选润色 | 不改变含义的语序、美观或个人偏好：通常留到下一期或下次维护，不为了全平台字面一致反复打扰作者。 |

纠错先查本地内容源，再查实际引用处：官网标题/重点导读/资讯卡、社媒稿、图片文字、来源索引、灵感 Markdown 和导出包。没有引用该句的文件不强改；不可改的已发平台另给更正说明方案。分别登记“本地已改、后台待改、线上待部署/已核验”，不能用历史 published 状态或旧预览认可证明新版已发布。
