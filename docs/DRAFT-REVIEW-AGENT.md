# 草稿后独立轻量审查 Agent

## 目的与边界

这是草稿生成后的独立理解与反向质疑门禁，不是新的总指挥，也不重新做整期选题研究。派发时必须明确它的本轮身份（例如“科技新闻编辑”“AI 入门级讲师”或“反向质疑审查者”）、输入范围和回执格式；身份是检查视角，不是事实凭证。它只审查最终期刊 JSON 和渲染文字，必要时才回源核对触发问题的事实。它不取得远端、平台或发布权限，不修改稿件；主 Agent 根据回执决定是否修订。

## 触发时机

完成一期 issue JSON 并运行 `content:validate` 后、派生平台稿和最终排版前执行。需要页面文字时生成本地候选渲染供盲读；真实预览验收仍在修订通过后进行。任何 `return` 都必须修订后重新审查；没有独立回执，不得把草稿称为已完成预览验收。

## 盲读检查

先只看标题、摘要、情报卡的“内容详情”和“造成的影响”，暂不看来源、编辑备注或主 Agent 的解释，记录一个普通读者会卡住的原句。逐卡检查：

1. 能否用白话回答发生了什么、谁现在能用/处于什么阶段、为什么值得注意。
2. 首次出现的缩写和专业名词是否在卡内解释；不能把术语表当作正文缺失的替代品。
3. 是否漏掉会改变判断的资格、地区、价格、版本、权限、成本、稳定性、隐私或回滚条件。
4. 产品入口是否被准确区分：ChatGPT 工作模式、普通对话（Chat）、Codex、API、网页端和命令行不能互相代称；标题是否把子入口状态错误扩大为整个产品状态。
5. 是否过短到必须打开来源才能理解基本事实；复杂概念不得为了字数而删掉必要背景。
6. 造成的影响是否有一个有证据支持的“先做什么/先别做什么”，且没有把 GA、热门度或接入能力写成生产可用。
7. 数字是否写出单位、方向和比较对象；输入/输出、缓存/标准、每次任务/每百万 token 不能用斜杠或省略词混写。
8. “造成的影响”是否写后果而不是重复价格、上下文或功能清单；编辑推断是否和来源事实分开。
9. 基础词是否重复解释；新产品、缩写和专门能力是否只在正文或术语区一个位置解释，且回读前两期术语去重记录。
10. 是否先用场景说明“它帮谁完成什么事”，再引入产品术语；技术细节是否通过价格、版本、权限、测试条件和限制保留，而不是堆叠缩写。
11. 是否同时通过“新手回读”和“专业回读”：前者能复述主线和后果，后者能据事实与限制判断结论边界。
12. 两栏内容是否存在明显的视觉失衡：相差约 2～3 行以内可由外层卡片等高处理；超过 3 行时，检查是否需要补充有证据支撑的背景、影响对象、后果或边界。不得建议用重复事实和空话填充；英文专名或固定词组不得因换行变成难以理解的孤立词。

整期再检查：摘要/导读是否覆盖重点卡片，卡片之间是否矛盾或重复宣传，是否有明显漏报。这个 Agent 不重新评价选题热度，也不替代逐条来源核验。

## 角色与派发

- **独立草稿审查者**：盲读标题、内容详情、造成的影响，检查普通读者能否理解。
- **反向质疑者**：逐句追问“这是来源事实还是编辑推断？删掉条件会不会误导？是否把宣布、预览、部分开放写成生产可用？”
- **AI 入门级讲师**：只审基础词库、术语新旧判断、解释位置和前两期去重；不替读者背书技术参数。
- **科技新闻编辑**：只审影响段是否说明证据带来的后果，删除把细节重复成影响的句子。

同一 Agent 可以在一次派发中承担多个明确角色，也可以拆成多个子 Agent；主 Agent 记录实际角色、读取材料和每个角色的结论。子 Agent 不能只收到“帮忙看看”，也不能看到主 Agent 的预设结论后再顺着确认。

## 回执格式

只返回三态之一，并附最小证据：

- `pass`：没有影响理解的阻断项，可继续人工预览。
- `return`：关键事实、限制、术语或行动边界缺失/误导，列出卡片 ID、原句和必须补什么；修订后重审。
- `advisory`：不阻断当前交付的可读性建议，列出建议修订及影响范围。

回执需记录稿件版本、审查范围、三态结论和每卡阻断理由（如有），写入现有 `findings.md` 或 `progress.md`，不另建事实库。审查结论不能代替作者立场确认、来源核验或公开发布授权。
