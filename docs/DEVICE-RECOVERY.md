# 在新设备上继续工作

代码仓库保存程序、测试和通用说明。它不是完整的工作资料备份：每期稿件、图片、来源库、运行记录和本机控制面另行保管。只克隆仓库，无法继续所有编辑任务。

## 先准备两份材料

1. 经确认已同步的代码版本及其完整提交号。没有远端回读确认的版本，仍只是本地候选。
2. 由操作者通过受控私有介质带走的工作资料，以及对应文件清单和校验值。保持原相对目录。先放入独立恢复目录核对，再处理与代码副本的重叠文件；不要直接覆盖两边不同的成果。

私有材料包括 `content/issues/`、`content/sources.json`、`public/images/issues/`、`exports/`、`每一期底稿/`、`.local/source-library/`、`ops/runs/`、`ops/weekly-run-state.json`、`task_plan.md`、`findings.md`、`progress.md` 和必要本机规则。按具体任务恢复，原始证据与旧版本保留。它们不能因为换机而加入公开仓库。

## 安装并验证代码环境

先安装 Git、项目支持的 Node.js 和 `package.json` 指定版本的 pnpm。本次准备采用 Windows、Node.js 24.16.0、pnpm 11.5.2；其他环境需要重新验证。Python 脚本需要 Python 3。依赖以 `pnpm-lock.yaml` 为准，不复制旧设备的 `node_modules`、`.next` 或构建缓存。

在新设备选择空目录后运行：

```powershell
git clone https://github.com/RongNianXin/ai-outpost.git
cd ai-outpost
git rev-parse HEAD
pnpm.cmd install --frozen-lockfile
pnpm.cmd test
pnpm.cmd ops:test
pnpm.cmd lint
pnpm.cmd typecheck
pnpm.cmd build
```

目的：确认拿到的是约定版本，依赖与锁文件一致，程序能通过检查并生成网页。预期是提交号匹配交付记录、命令成功结束；警告与跳过项另行核对。若失败，保留失败命令、退出状态和第一处错误，不用更新锁文件、重装全部工具或关闭检查来掩盖问题；给维护 AI 提供脱敏日志。新设备首次安装和恢复，在实际完成前均属未验证。

## 恢复任务资料与权限

- 对照私有清单检查文件数量、大小和 SHA256。代码测试通过只证明代码可运行，不证明稿件、图片和断点齐全。
- 已审导出包的清单可能包含旧设备绝对路径。恢复后由维护 AI 逐项核对：优先使用相同的工作目录；目录改变时，保留原清单，在确认新旧文件哈希对应后仅修正路径。缺文件先恢复，不能通过访问预览或重新生成覆盖已审内容。
- 恢复任务记录后，先读当前任务和未完成项，再核对引用文件是否存在。若期刊状态与发布回执不一致，保留分歧并核验，不能自行再次发布。
- 本机工作流启用声明可能指向旧设备绝对路径。先恢复其正式规则来源，核对清单，再按实际位置修正本机入口。旧总指挥身份记录只作历史，不能在新聊天中直接沿用身份。
- 登录、凭据和平台权限在新设备单独配置。`.env.example` 只有空模板；不要把真实密钥、浏览器资料、Cookie 或账号数据库放入迁移包或公开仓库。缺凭据仅暂停相应平台功能。
- 如需来源研究，恢复私密来源库后再执行 `pnpm.cmd content:research:start`。成功加载本地资料不表示原网站访问成功。
- 远端写入、公开发布、部署和自动化仍各自核权；换机恢复不产生新的权限，也不恢复旧调度。

## 检查本机页面

运行 `pnpm.cmd dev` 后打开 `http://127.0.0.1:3100/`，核对首页和一篇实际需要续作的文章；没有恢复私有稿件时只会显示仓库现有内容。要预览指定草稿，按 [WORKFLOW.md](WORKFLOW.md) 的草稿预览步骤设置本进程变量。迁移稿预览还需要恢复对应的导出文件。

目的：确认真实页面、图片和稿件属于正确版本。成功时目标页面可访问且内容匹配；否则回传页面地址、错误截图和服务日志，隐藏账号与密钥。查看完成后停止自己启动的服务。

恢复完成的条件是代码、私有资料、任务断点和所需本机页面均有实际核对结果；未恢复的资料、缺失目录或未验证环节须单列，不能统称“全部同步完成”。

## 工作目录改变时迁移已审稿包路径

由维护 AI 在独立恢复目录操作，确认没有其他程序同时修改导出文件。使用旧设备准备的私有 `inventory.json`（含 `worktrees[0].path`、`files[].path` 和 `files[].sha256`），先执行只读计划：

```powershell
python scripts/ops/relocate-export-manifests.py --inventory <私有清单绝对路径> --root <新项目绝对路径> --manifest exports/publish/<slug>/manifest.json
```

程序会验证所选清单及其引用文件的原字节，并递归处理引用到的子清单。预期输出 `dry_run`、已核文件数量及待改清单；此时不修改文件。确认范围与实际恢复目录匹配后，在同一命令末尾加 `--apply`：它先保留原清单到新目录的 `.local/export-path-backups/`，再仅改路径，不重新生成正文、图片或封面。不要重复用旧清单对已经迁移过的文件执行。

文件缺失、哈希不同、目录越界或链接目录均会拒绝；先保留脱敏错误和原件，补齐正确文件后再核验，不关闭检查。写盘失败时停止预览，并根据返回前已保存的备份检查受影响文件，不假定多文件写入具备整体事务保证。恢复后仍须实际打开本机页面；迁移工具的合成测试通过不代表新设备验收已完成。

工具离线检查命令：`python scripts/ops/relocate-export-manifests.checks.py`。
