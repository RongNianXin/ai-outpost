# AI 事实核验协议

## 目标

把官方事实与有归因的第三方实测转换成可信、简短的中文情报，并尽量减少用户人工参与。用户不负责阅读英文原文，也不需要修改 JSON。

## 强制角色

同一条资讯必须经过以下检查角色；每轮必须重读原始来源，不能只读前轮摘要。独立 Agent 需获授权；无授权时分轮串行完成并如实记录，不声称多人独立验证。

自 2026-09-12 起，每周首轮信息源检索完成后必须使用一个独立审查子 Agent。旧的“无授权时串行复核”仅保留给历史记录和平台确实不支持子 Agent 的临时降级；新的周刊成稿在缺少独立审查时应停在候选阶段并报告受影响项。

### 角色 A：候选发现 Agent

任务：

1. 同时查官方资料、独立评测和可信博主的一手实测；先列本周最重磅三项，交稿前复查遗漏。按 CONTENT-OPS 的多层来源规则分类。
2. 记录页面标题、完整 URL、发布者、发布日期和发现时间；日期精度不足不得补造时分。按 CONTENT-OPS 留下逐入口访问结果与覆盖缺口，重大模型发布不以社交热度为准入条件，正式六条核对 1–2 条非官方主体内容。
3. 媒体转载、社区讨论和搜索摘要只作线索；转到署名原文核对。传闻不作事实，日期待确认时不得编造。
4. 提取可能影响 AI 应用开发者的变化，不生成影响结论。

固定输出：

- 候选 ID
- 原始标题
- 原始 URL
- 发布日期
- 来源类型
- 一句话事实
- 原文中的限制词
- 建议保留或淘汰

### 角色 B：来源真实性 Agent

任务：

1. 核对厂商或作者身份与原始发布平台，不接受拼写相似域名和内容镜像。第三方须核对实验任务、环境、方法、利益关系和局限，名气不能代替证据。
2. GitHub 来源必须确认仓库位于官方组织，Release 标签真实存在。
3. 检查页面是否为当前页面而不是旧页面、缓存页或搜索结果片段。
4. 检查 URL 跳转后的最终域名。
5. 核对页面标题、作者或组织、发布日期是否互相一致。
6. 对价格、模型退役、安全和法律信息，至少再找一份官方文档交叉支持。
7. 官方文档没有显示发布日期时必须记录为空，不得用关联公告日期代替。

固定输出：

- `PASS`：来源身份明确
- `REVISE`：来源可信，但日期或页面类型需要修正
- `REJECT`：无法确认来源身份或原始证据
- 厂商或作者身份判断依据
- 最终 URL
- 日期判断依据
- 第二官方来源（需要时）

### 角色 C：事实与证据映射 Agent

任务：

1. 把每个可发布事实拆成单独句子。
2. 为每个句子定位原始页面章节、表格行或 Release 条目。
3. 核对数字、日期、模型 ID、套餐、地区、资格和版本。
4. 保留 preview、beta、部分用户、逐步开放等限定词。
5. 禁止把官方营销评价当客观事实；第三方观察必须有归因与条件。未观看或未复现的材料明示核验范围。
6. 直接摘录必须很短，其余使用中文转述。

固定输出：

- 中文事实句
- 支持来源
- 证据位置
- 简短证据转述
- 必须保留的限制条件
- `SUPPORTED`、`PARTIAL` 或 `UNSUPPORTED`

### 角色 D：反向质疑 Agent

任务：

1. 假设当前草稿可能是错的，主动寻找反例和遗漏条件。
2. 检查是否混淆“宣布、开放预览、正式可用、停止服务”。
3. 检查未来日期是否被写成已经发生。
4. 检查“所有用户、免费、生产可用、最好、取代”等绝对表达。
5. 检查分析是否被伪装成官方结论。
6. 检查同一厂商的两个官方页面是否互相冲突。

固定输出：

- `PASS`、`DOWNGRADE` 或 `REJECT`
- 最可能误导读者的句子
- 建议降低的措辞
- 尚未解决的冲突

### 角色 E：中文编辑 Agent

任务：

1. 只使用已经通过的事实，不新增数据和结论。
2. 首次出现英文缩写时给出中文解释。
3. 用初学者能理解的中文写清“内容详情”（发生了什么）和“造成的影响”（对行业或对个人开发者，逐卡只聚焦一边）。
4. 将行动参考写成可选的资讯处理建议，不强行转成动手任务；它只在展开区提供，不占默认卡片主阅读区。
5. 避免制造产品机会或实践任务，除非后续版本重新启用相关板块。

固定输出：

- 内容详情：按新闻复杂度弹性撰写，原则上不超过 200 字；简单事实不为凑字数扩写
- 造成的影响：按新闻复杂度弹性撰写，原则上不超过 200 字，按当期内容只聚焦行业或个人一侧
- 通俗术语解释
- 行动参考和风险提示（供展开区使用）

### 角色 F：总质检 Agent

任务：

1. 汇总 A 至 E 的输出，检查字段是否齐全。
2. 任一事实出现 `REJECT` 或 `UNSUPPORTED`，直接删除。
3. `PARTIAL` 或 `DOWNGRADE` 必须修改后重新送审。
4. 高风险事实没有第二官方来源时删除。
5. 输出全中文自动验证摘要，不要求用户阅读英文。

最终输出：

- 通过的事实
- 被删除的事实及原因
- 尚存风险
- 标题建议
- 适合发布、需要修改或本期不发布

### 独立审查者：首轮来源与成稿门禁

独立审查者在执行者完成首轮来源检索并冻结输入后建立。它不参与选题发现，不继承执行者结论，不写产品、中央状态或远端，只向当前总指挥返回审查意见。

冻结输入至少包含：本期时间窗与实际检索时刻、全部候选及淘汰理由、原始 URL 与必要证据摘录、可见热度信号及抓取时刻、拟用标题、结构化稿和派生 Markdown。私密来源名单、内部评价和无关候选不得离开本项目允许范围。

逐条检查：

1. 事件是否在检索时刻前 168 小时内；日期精度不足、旧闻翻炒或更新页冒充新发布时标记 `REJECT`。
2. 讨论信号是否真实可见、记录时刻和范围是否明确；热度只用于排序，不替代事实。另评估变化幅度、受众关联和证据强度。
3. 来源主体、最终 URL、发布时间、数字、套餐/型号、适用地区与用户范围是否准确；价格和服务暂停须有两份一手证据，冲突未解时 `REJECT`。
4. 是否复制媒体标题、结构、长段文字或受限素材；遇明确禁止转载、许可不明或无法回溯原始来源时，删除受影响表达或素材。
5. 是否含时政内容，或对国家、地区、政府、公职部门作评论；边界不清的候选不得进入公开稿。
6. 标题是否忠实、不夸大、不虚假；正文是否自然、无明显模板腔，同时保留必要限定和 AI 辅助/素材标识。
7. Markdown 是否与结构化稿一致，卡片、排序、事实、限制、来源和链接是否完整，是否泄露私密资料、本机地址或内部备注。
8. 将全部合格信息按综合关注度从高到低排序；同时单列“高讨论但低证据”和“高影响但讨论量待形成”，不得用一个伪精确总分掩盖差异。

固定输出为：候选 ID、`PASS`/`REVISE`/`REJECT`、八项检查结论、证据与缺口、建议顺序、必须修改项。默认最多两轮：第一轮审查，执行者修订后第二轮复核；只有出现新的可验证证据或预先约定条件时可进行第三轮，第三轮后本批必须结束。总指挥逐项接受、驳回或降级意见并负责最终写入，审查者不得取得中央调度权。

## 用户只做轻量判断

1. 标题是否清楚、不夸张。
2. 这期内容对自己是否有用。
3. 是否需要继续调整页面表达。

用户不负责确认英文原文、不修改状态字段，也不需要判断技术实现细节。

进入预览记录 `previewApprovedAt`。公开发布时记录 `publishedAt`；`publicationApprovedAt` 作为旧字段保留兼容，不再作为发布闸门。

## 自动淘汰规则

- 来源身份不明，或第三方结果没有原始依据、归因和适用条件。
- 无法确认发布日期。
- 事件首次公开时间距实际检索时刻超过 168 小时，或无法证明落在窗口内。
- 原文找不到直接证据。
- 两个 Agent结论冲突且无法解决。
- 明确禁止转载却复制其表达/素材，或版权边界无法收敛。
- 含时政内容，或对国家、地区、政府、公职部门作评论。
- 需要用户继续阅读英文才能判断。
- 结论属于法律、医疗、投资或重大安全建议，但证据不足。

## 状态含义

- `unverified`：尚未核验，禁止发布。
- `ai_checked`：完成一轮检查，禁止发布。
- `ai_cross_checked`：完成来源、映射和反向检查，可以进入本地预览；不表示实验已复现或必然有多个独立 Agent。
- `draft`：草稿，网站不展示。
- `approved`：已完成本地预览准备，仅本地开发预览可见，生产网站不展示。
- `published`：已填写公开发布时间，允许进入公开网站。
- `corrected`：已经公开，但附带更正记录。
