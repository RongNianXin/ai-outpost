# AI 事实核验协议

## 目标

把英文官方信息转换成可信、简短的中文情报，并尽量减少用户人工参与。用户不负责阅读英文原文，也不需要修改 JSON。

## 强制角色

同一条资讯必须经过以下相互独立的角色。后一个 Agent不能只阅读前一个 Agent的摘要，必须重新打开来源。

### 角色 A：候选发现 Agent

任务：

1. 只查白名单中的官方博客、官方文档、官方更新日志和官方 GitHub Release。
2. 记录页面标题、完整 URL、发布者、发布日期和发现时间。
3. 删除媒体转载、搜索摘要、社交媒体传闻和日期不明内容。
4. 提取可能影响 AI 应用开发者的变化，不生成影响结论。

固定输出：

- 候选 ID
- 官方标题
- 官方 URL
- 发布日期
- 来源类型
- 一句话事实
- 原文中的限制词
- 建议保留或淘汰

### 角色 B：来源真实性 Agent

任务：

1. 检查域名是否属于官方组织，不接受拼写相似域名和内容镜像。
2. GitHub 来源必须确认仓库位于官方组织，Release 标签真实存在。
3. 检查页面是否为当前页面而不是旧页面、缓存页或搜索结果片段。
4. 检查 URL 跳转后的最终域名。
5. 核对页面标题、作者或组织、发布日期是否互相一致。
6. 对价格、模型退役、安全和法律信息，至少再找一份官方文档交叉支持。
7. 官方文档没有显示发布日期时必须记录为空，不得用关联公告日期代替。

固定输出：

- `PASS`：来源身份明确
- `REVISE`：来源可信，但日期或页面类型需要修正
- `REJECT`：无法证明是官方来源
- 官方身份判断依据
- 最终 URL
- 日期判断依据
- 第二官方来源（需要时）

### 角色 C：事实与证据映射 Agent

任务：

1. 把每个可发布事实拆成单独句子。
2. 为每个句子定位官方页面章节、表格行或 Release 条目。
3. 核对数字、日期、模型 ID、套餐、地区、资格和版本。
4. 保留 preview、beta、部分用户、逐步开放等限定词。
5. 禁止把官方营销评价当成客观事实。
6. 直接摘录必须很短，其余使用中文转述。

固定输出：

- 中文事实句
- 支持来源
- 证据位置
- 简短证据转述
- 必须保留的限制条件
- `SUPPORTED`、`PARTIAL` 或 `UNSUPPORTED`

### 角色 D：反向质疑 Agent

任务：

1. 假设当前草稿可能是错的，主动寻找反例和遗漏条件。
2. 检查是否混淆“宣布、开放预览、正式可用、停止服务”。
3. 检查未来日期是否被写成已经发生。
4. 检查“所有用户、免费、生产可用、最好、取代”等绝对表达。
5. 检查分析是否被伪装成官方结论。
6. 检查同一厂商的两个官方页面是否互相冲突。

固定输出：

- `PASS`、`DOWNGRADE` 或 `REJECT`
- 最可能误导读者的句子
- 建议降低的措辞
- 尚未解决的冲突

### 角色 E：中文编辑 Agent

任务：

1. 只使用已经通过的事实，不新增数据和结论。
2. 首次出现英文缩写时给出中文解释。
3. 用初学者能理解的中文说明“发生了什么”和“与我有什么关系”。
4. 把产品机会明确标记为设想，不写成确定商机。
5. 实践任务不得默认要求购买 API、订阅或高配置电脑。

固定输出：

- 80 字以内的事实摘要
- 120 字以内的影响解释
- 通俗术语解释
- 产品机会设想及置信度
- 免费可执行的实践任务

### 角色 F：总质检 Agent

任务：

1. 汇总 A 至 E 的输出，检查字段是否齐全。
2. 任一事实出现 `REJECT` 或 `UNSUPPORTED`，直接删除。
3. `PARTIAL` 或 `DOWNGRADE` 必须修改后重新送审。
4. 高风险事实没有第二官方来源时删除。
5. 输出全中文自动验证摘要，不要求用户阅读英文。

最终输出：

- 通过的事实
- 被删除的事实及原因
- 尚存风险
- 标题建议
- 适合发布、需要修改或本期不发布

## 用户只做轻量判断

1. 标题是否清楚、不夸张。
2. 这期内容对自己是否有用。
3. 是否需要继续调整页面表达。

用户不负责确认英文原文、不修改状态字段，也不需要判断技术实现细节。

进入预览记录 `previewApprovedAt`。公开发布时记录 `publishedAt`；`publicationApprovedAt` 作为旧字段保留兼容，不再作为发布闸门。

## 自动淘汰规则

- 不是官方来源。
- 无法确认发布日期。
- 原文找不到直接证据。
- 两个 Agent结论冲突且无法解决。
- 需要用户继续阅读英文才能判断。
- 结论属于法律、医疗、投资或重大安全建议，但证据不足。

## 状态含义

- `unverified`：尚未核验，禁止发布。
- `ai_checked`：完成一轮检查，禁止发布。
- `ai_cross_checked`：完成独立交叉检查，可以进入本地预览。
- `draft`：草稿，网站不展示。
- `approved`：已完成本地预览准备，仅本地开发预览可见，生产网站不展示。
- `published`：已填写公开发布时间，允许进入公开网站。
- `corrected`：已经公开，但附带更正记录。
