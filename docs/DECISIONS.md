# 架构决策记录

## ADR-001：产品优先级

**决定：** V1 是个人优先、公开分享的低维护作品，暂不以商业化为目标。

**原因：** 项目作者时间有限，当前首先验证内容是否对自己有用。

## ADR-002：使用 Next.js

**决定：** 使用 Next.js 16、App Router 和 TypeScript。

**原因：** 虽然纯内容站可以采用更轻的框架，但 Next.js 更符合项目作者学习完整 AI Web 应用开发的目标。V1 通过静态导出控制复杂度和成本。

## ADR-003：采用静态导出

**决定：** GitHub Pages托管构建后的静态文件。

**原因：** 不需要应用服务器、数据库或运行时 AI 调用，部署成本低。未来需要动态功能时可迁移托管方式。

## ADR-004：JSON 是唯一事实源

**决定：** 每期使用经过 Schema 校验的 JSON 文件。

**原因：** JSON 容易被 AI 和程序稳定生成，能够严格校验枚举和引用关系。网页和公众号从同一数据生成。

## ADR-005：自动验证优先

**决定：** 不再把人工最终审核作为 V1 发布闸门。内容可信度主要依赖官方来源、AI 交叉核查、离线结构校验、联网链接检查和公开更正记录。

**原因：** 项目作者时间有限且不擅长英文。机械状态修改、英文来源检查和坏链检测应交给 AI 与脚本；页面只承诺“降低错误概率”，不承诺自动验证能替代官方来源。

## ADR-006：阶段版本

**决定：** 每个研发阶段形成一个 Git 提交和标签。

**原因：** 提供清晰的学习记录和稳定回退点，同时避免每个细小操作都产生版本噪声。

## ADR-007：子 Agent

**决定：** 只为独立、并行、边界明确的任务使用子 Agent。

**原因：** 并行研究、测试或代码审查可以提高质量；紧密耦合的小任务由主 Agent处理更可靠。
