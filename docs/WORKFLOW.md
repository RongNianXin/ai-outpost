# AI Outpost 工作流

本文把《工作流方案 2：轻量提示词卡片版》落到 AI Outpost 项目中，用于后续 Codex、Claude Code、DeepSeek 或其他 AI 接手。

## 当前项目阶段

AI Outpost 已完成 V1 公开发布，当前处于：

> 稳定周更自动化规划与第 002 期生产流程准备。

项目不是从零规划阶段，也不是继续大改 UI 阶段。第 001 期已公开发布，下一步优先验证每周内容生产能否尽量自动化、少人工介入，并在作者确认后上线。

## 接手时先读

新会话或新 AI 接手时，默认先读根目录三文件：

1. `task_plan.md`
2. `findings.md`
3. `progress.md`

只有当当前任务需要更详细背景时，再读取：

- `docs/PRODUCT.md`
- `docs/ARCHITECTURE.md`
- `docs/CONTENT-OPS.md`
- `docs/PROGRESS.md`

不要默认扫描全仓库。

## 日常开发规则

- 简单任务直接轻量执行。
- 复杂任务先说明执行方式，再进入设计、调试或验证流程。
- 只读取完成当前任务真正需要的文件。
- 修改范围保持最小，不提前实现 V2/V3。
- 当前优先级高于社媒平台接入：稳定官网周更、自动校验、确认上线。
- 完成后更新 `progress.md`。
- 如果发现长期有价值的约束、坑点或判断，更新 `findings.md`。
- 如果阶段状态、下一步或验收标准变化，更新 `task_plan.md`。

## 复杂任务规则

以下情况需要更重流程：

- 新子系统。
- 跨多个模块。
- 影响内容 schema、发布闸门、构建流程或部署流程。
- 涉及安全、成本、自动化发布、数据迁移或用户数据。
- 涉及周更运行状态、通知确认、中断发布或平台分发。
- 修复难以定位的 Bug。
- 最终发布前验收。

重流程要求：

1. 先澄清目标和验收标准。
2. 必要时给 2-3 个方案和推荐方案。
3. 获得确认后再修改。
4. 变更后运行必要验证。
5. 把结果写入 `progress.md`，把长期结论写入 `findings.md`。

## Git 规则

- 默认不自动提交 Git。
- 默认不推送、不合并、不创建 PR。
- 只有用户明确要求“保存版本”“提交”“打标签”等，才执行 Git 操作。
- 执行 Git 前先检查 `git status --short`。
- 提交后报告 commit 和 tag。

## 发布前检查

公开发布前必须确认：

- 本期内容已经完成 AI 交叉核查、离线校验和发布前链接检查。
- `publishedAt` 已填写。
- 期刊状态已切换为 `published`。
- 内容校验、链接检查、公众号导出、类型检查、lint、测试和构建均通过。
- 首页、归档页、关于页和期刊详情页可访问。
- 移动端无横向滚动。
- 项目作者已确认发布；如果周更运行状态是 `paused`、`draft_only` 或 `emergency_stop`，不得发布。

## 周更自动化规则

- 官网是主站和唯一主事实源。
- 每周优先自动完成候选收集、筛选、事实映射、AI 交叉核验、中文草稿和预览。
- 上线前保留人工确认关卡；不允许 AI 全自动绕过确认直接发布。
- 内容不足时允许短版或跳过。
- 分享包可以生成，但公众号、小红书、X/Twitter 前期不自动发布。
- 一键确认、微信/企业微信通知和平台接口能力均待确认；确认前不能写成已实现能力。

## 不要做

- 不把 AI Outpost 与“灵感雷达”合并。
- 不引入数据库、CMS、登录、聊天框或用户 API Key。
- 不开发短视频生成、自动剪辑或自动发布。
- 不把公众号、小红书或 X/Twitter 自动发布作为近期硬目标。
- 不为了未来功能提前建设复杂平台。
- 不把未经自动验证和发布前构建检查的内容发布到生产站点。
