# AI Outpost 工作流

推广与分发的现行入口是 [PROMOTION.md](PROMOTION.md)。更新相关文档前先读该文件并搜索同主题旧说明；本文保留工程流程，不重复维护平台当前状态。

本文把《工作流方案 2：轻量提示词卡片版》落到 AI Outpost 项目中，用于后续 Codex、Claude Code、DeepSeek 或其他 AI 接手。

## 当前项目阶段

AI Outpost 已完成 V1 公开发布，当前处于：

> 稳定周更与本机三平台发布控制页验收。

项目不是从零规划阶段。第 001 期已公开发布，第 003 期用于验证每周内容刷新、真实预览和官网/公众号/小红书三个独立发布出口。

## 接手时先读

新会话或新 AI 接手时，默认先读根目录三文件：

1. `task_plan.md`
2. `findings.md`
3. `progress.md`

只有当当前任务需要更详细背景时，再读取：

- `docs/PRODUCT.md`
- `docs/ARCHITECTURE.md`
- `docs/CONTENT-OPS.md`
- `docs/PROGRESS.md`

不要默认扫描全仓库。

## 日常开发规则

- 简单任务直接轻量执行。
- 复杂任务先说明执行方式，再进入设计、调试或验证流程。
- 只读取完成当前任务真正需要的文件。
- 修改范围保持最小，不提前实现 V2/V3。
- 当前优先级高于社媒平台接入：稳定官网周更、自动校验、确认上线。
- 完成后更新 `progress.md`。
- 如果发现长期有价值的约束、坑点或判断，更新 `findings.md`。
- 如果阶段状态、下一步或验收标准变化，更新 `task_plan.md`。

## 复杂任务规则

以下情况需要更重流程：

- 新子系统。
- 跨多个模块。
- 影响内容 schema、发布闸门、构建流程或部署流程。
- 涉及安全、成本、自动化发布、数据迁移或用户数据。
- 涉及周更运行状态、通知确认、中断发布或平台分发。
- 修复难以定位的 Bug。
- 最终发布前验收。

重流程要求：

1. 先澄清目标和验收标准。
2. 必要时给 2-3 个方案和推荐方案。
3. 获得确认后再修改。
4. 变更后运行必要验证。
5. 把结果写入 `progress.md`，把长期结论写入 `findings.md`。

## Git 规则

- 默认不自动提交 Git。
- 默认不推送、不合并、不创建 PR。
- 本地提交或打标签须有明确授权；授权可以包含在首次本地执行包中，无须在修复、验证完成后再问一次。远端写入另按执行前最终确认处理，不能从本地授权推定。
- 执行 Git 前先检查 `git status --short`。
- 提交后报告 commit 和 tag。

## 当前常用命令

```powershell
pnpm.cmd content:validate
pnpm.cmd content:check:links
pnpm.cmd content:export:wechat
pnpm.cmd content:preview:url
pnpm.cmd typecheck
pnpm.cmd lint
pnpm.cmd test
pnpm.cmd build
```

本地预览：

```powershell
pnpm.cmd dev
```

本机发布控制页：

```powershell
pnpm.cmd publish:console
```

默认地址：`http://127.0.0.1:3101/`。控制页只绑定本机，并把“生成/预览”和“最终发送”分开；所有外部写入都要求输入与期号绑定的确认句。

内容生成或修改完成后，AI 必须把 `content:preview:url` 返回的详情页直接打开在当前 Codex 浏览器中，供用户查看真实排版；不能只发文本草稿或 URL。

默认地址：

```text
http://127.0.0.1:3100/
```

## 发布前检查

公开发布前必须确认：

- 本期内容已经完成 AI 交叉核查、离线校验和发布前链接检查。
- `publishedAt` 已填写。
- 期刊状态已切换为 `published`。
- 内容校验、链接检查、公众号导出、类型检查、lint、测试和构建均通过。
- 首页、归档页、关于页和期刊详情页可访问。
- 移动端无横向滚动。
- 项目作者已确认发布；如果周更运行状态是 `paused`、`draft_only` 或 `emergency_stop`，不得发布。

## 周更自动化规则

- 先列本周三件重磅候选，交稿前复查遗漏；官方确认发布事实，独立评测和可信博主补充实际体验，分别归因。具体证据与准入规则以 CONTENT-OPS 为准。

- 官网是主站和唯一主事实源。
- 每周优先自动完成候选收集、筛选、事实映射、AI 交叉核验、中文草稿和预览。
- 详情页标题默认拆成可验证的短主句与补充标题；每期最多使用一张可选原创无字主视觉，情报卡不机械配图。
- 事实稿完成后先做独立文风改写，再运行 `content:validate` 的模板词检查；自动检查不能冒充 AI 检测器，真实页面人工审核仍是发布门禁。
- 上线前保留人工确认关卡；不允许 AI 全自动绕过确认直接发布。
- 内容不足时允许短版或跳过。
- 公众号与小红书均先生成预览和派生稿；公众号先入草稿箱，小红书先发私密测试，验证后再开放正式发送。
- 公众号 AppSecret 和小红书 Cookie 只保存在本机，不进入 GitHub、日志或聊天。
- 三个平台分别保留确认门禁和幂等回执，不提供绕过审核的“一键全发”。

## 不要做

- 不把 AI Outpost 与“灵感雷达”合并。
- 不引入数据库、CMS、登录、聊天框或用户 API Key。
- 不开发短视频生成或自动剪辑。
- 不在无人审核时自动发布公众号、小红书或官网。
- 不为了未来功能提前建设复杂平台。
- 不把未经自动验证和发布前构建检查的内容发布到生产站点。
