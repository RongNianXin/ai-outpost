# 第 003 期执行任务包

## 任务目标

用最近一个完整自然周的官方信息，恢复 AI Outpost 的内容生产闭环：候选收集、筛选、事实核验、中文编辑、结构化草稿、公众号稿、小红书分享包、本地预览和发布前验证。

本任务包把用户输入的“0037”解释为“第 003 期”。仓库目前只有 001、002，继续使用 `issue-003` 能保持编号连续。

## 目标受众 / 使用对象

- 面向 AI 应用创造者、独立开发者和技术基础仍在积累的产品负责人。
- 用户只需要阅读中文预览、风险摘要并决定是否发布。

## 输入材料

- 周期窗口：`2026-08-24` 至 `2026-08-30`，时区 `Asia/Shanghai`。
- 状态入口：`task_plan.md`、`findings.md`、`progress.md`。
- 内容规则：`docs/CONTENT-OPS.md`、`docs/FACT-CHECK-PROTOCOL.md`。
- 数据契约：`lib/content/schema.ts`、`content/sources.json`。
- 历史参照：`content/issues/issue-001.json`、`content/issues/issue-002.json`。

## 已确认事实

- 第 001 期已发布；第 002 期仍为 `approved`，不会进入生产构建。
- 官网是唯一主事实源，公众号和小红书内容只能从期刊 JSON 派生。
- 当前 GitHub 周更任务只会校验已有内容，不会自动检索或调用 AI 生成新一期。
- GitHub 周更任务已因长期无仓库活动停用，恢复属于远端写操作。

## 合理假设与待确认事项

- 假设第 003 期只覆盖最近一个完整自然周，不回填 6 月以来全部空档。
- 假设本轮先完成可审核草稿，不公开发布。
- 用户是否确认公开发布、恢复 GitHub workflow 和触发远端测试，均留到本地验收完成后单独确认。

## 核心变量

- 候选上限：20 条。
- 正式情报卡：最多 6 张；高质量内容只有 1 至 3 条时允许短版。
- 重点变化：最多 3 条。
- 前沿概念观察：最多 1 条，且必须明确官方背书弱、概念未稳定。
- 内容状态：本轮最高为 `approved`；`publishedAt` 和 `publicationApprovedAt` 保持 `null`。
- 运行模式：`draft_only`，必须保留人工发布确认。

## 最小可行路径

1. 检查 OpenAI、Anthropic、Google AI、GitHub、Microsoft、Cursor、MCP 等白名单官方来源。
2. 记录标题、URL、发布者、发布日期、具体证据位置和一句话事实。
3. 淘汰日期不明、只有转载、营销大于事实、与目标读者关系弱的候选。
4. 对保留候选做来源真实性、事实映射、反向质疑和中文编辑；标题拆成短主句与补充标题，避免把六条摘要塞入同一个超大标题。
5. 生成 `content/issues/issue-003.json`，按需要配置一张原创无字主视觉，并写入本期运行状态与运行日志。
6. 生成公众号 Markdown 和小红书图文卡片文案，不连接平台账号。
7. 执行内容校验、链接检查、类型检查、lint、测试和静态构建。
8. 运行 `pnpm.cmd content:preview:url -- --slug 2026-08-24-agent-security-cursor-models-video-generation`，启动开发服务，并在当前 Codex 浏览器直接打开页面；确认第 003 期可见且生产构建没有误公开。
9. 输出中文确认摘要，等待用户决定发布、保留草稿或放弃本期。

## 输出格式

- `content/issues/issue-003.json`
- `ops/weekly-run-state.json`
- `ops/runs/2026-W36.json`
- `exports/wechat/<issue-003-slug>.md`
- `exports/social/<issue-003-slug>.md`
- 本地详情页：`http://127.0.0.1:3100/issues/<issue-003-slug>/`
- 中文确认摘要：核心变化、删除候选、最高风险、验证结果和发布建议。

## 验收标准与验证方式

- 每条硬事实至少有一个一手官方来源，发布日期落在本期窗口内。
- 来源 URL 必须通过白名单检查；事实句能定位到官方页面具体段落或更新条目。
- 分享包不得增加期刊 JSON 中没有的事实。
- 主视觉为项目本地资产，无第三方 Logo、虚构产品 UI 或来源不明素材；移除图片后页面仍可正常显示。
- 自动文风检查无高风险模板词命中，真实网页仍保留人工自然度审核。
- 以下命令通过：

```powershell
pnpm.cmd content:validate
pnpm.cmd content:check:links
pnpm.cmd content:export:wechat
pnpm.cmd typecheck
pnpm.cmd lint
pnpm.cmd test
pnpm.cmd build
```

- 本地预览返回 200；生产构建只包含 `published` 或 `corrected` 内容。
- 明确 404、证据冲突或结构/测试失败属于阻断问题；403、405、超时按来源和替代证据决定是否降级为警告。

## 自动提醒方案

- Codex 周期任务：每周六在当前聊天检查本期是否已生成、验证或等待确认，并给出下一步。它依赖电脑开机、桌面应用运行和本地项目可访问。
- GitHub Actions + Server酱：每周六云端运行已有校验并推送微信；电脑可以关机，但它目前不会生成新资讯。
- 两条提醒不得自动切换 `published`、触发部署或绕过用户确认。

## 风险、回滚或降级方案

- 内容不足：生成短版或跳过报告，不凑数。
- 外部页面不可访问：寻找同一发布方的官方替代页；无法核验则删除候选。
- 本地验证失败：保持 `draft`，记录失败步骤，不触发任何远端动作。
- 草稿质量不足：删除有争议卡片，保留上一期线上内容。
- 提醒任务误触发：暂停 Codex 周期任务；GitHub workflow 保持禁用，直到用户再次确认。

## 不要做（排除项）

- 不回填停更期间全部新闻。
- 不自动发布官网、公众号或小红书。
- 不新增数据库、CMS、账号系统、付费 API 或长期服务器。
- 不把媒体转载、社交热度或 AI 推断写成官方事实。
- 不在聊天、仓库、日志或文档中暴露 Server酱密钥。

## 完成定义

以下任一结果可视为本轮完成：

- 可审核草稿：第 003 期及分享包通过验证，停在人工发布确认点。
- 短版草稿：只有 1 至 3 条高质量内容，但证据与验证完整。
- 合理跳过：没有足够可靠内容，保留候选与淘汰原因，不生成虚假周报。

未经用户明确确认，不得把“可审核草稿”升级为“已发布”。
